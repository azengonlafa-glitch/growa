# growa — รีวิวการเข้าถึงและ UX ของหน้าเว็บ

ตรวจเมื่อ 2026-10-23 ด้วยสกิล `web-design-guidelines` (อ่านโค้ดอย่างเดียว ยังไม่ได้เรนเดอร์หน้า ไม่ได้ทดสอบด้วย screen reader) แล้วผู้ดูแลโปรเจกต์เทียบกับโค้ดจริงอีกรอบ รายการที่เขียนว่า **ยืนยันแล้ว** คือเปิดดูบรรทัดนั้นแล้วเป็นจริง

กลุ่มผู้ใช้ที่ต้องคำนึงถึงที่สุดคือผู้สูงอายุและผู้ดูแล จึงเรียงตามผลกระทบต่อกลุ่มนี้

## ข้อที่รายงานดั้งเดิมพูดเกินจริง (ไม่ต้องแก้ตามนั้น)

- **"ไม่มี focus ที่เห็นชัดในปุ่มตัวเลือก" ไม่ใช่ blocker:** ใน CSS ไม่มี `outline: none` เบราว์เซอร์จึงยังแสดงกรอบโฟกัสมาตรฐานให้เอง การเพิ่ม `:focus-visible` ที่เข้ากับธีมเป็นการปรับปรุง ไม่ใช่ช่องโหว่
- **"ปุ่มที่ Login ส่ง `className` แล้วเสียคลาส" ไม่เป็นจริง:** ปุ่มบัญชีเดโมส่ง `className="btn btn-secondary demo-account"` ครบอยู่แล้ว (ปัญหาจริงคือ `Button` ไม่รวม className แต่ตอนนี้ไม่มีผล)
- **"รายการร้านยาไม่จำกัดจำนวน" ไม่เป็นจริง:** `searchDirectory` ตัดผลที่ 30 ร้านอยู่แล้ว

## ผ่านแล้ว

`lang="th"`, ไม่บล็อกการซูม, ไม่มี `transition: all`, ไม่มี `<div onClick>`, input มี label ครบ, ไอคอนตกแต่งมี `aria-hidden`, มีสถานะ loading/empty/error ครบ, Notice แบบ error มี `role="alert"`, ใช้ safe-area ที่แถบล่าง

## ที่ยังไม่ได้ตรวจ

contrast จริง (ต้องเรนเดอร์หน้า), การใช้ screen reader จริง, `web/src/lib/*` และเนื้อหาภาษาไทยของข้อความ
